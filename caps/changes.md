# 变更记录 — Caps 模块

本模块所有重要改动记录于此。格式参考 [Keep a Changelog](https://keepachangelog.com/)，版本遵循语义化版本。

> 文中出现的键盘名（如 QK61/NUT65）仅为**参考示例**；共享层不含任何键盘专属实现或测试。
> 流程要求见 [`../qmk/README.md`](../qmk/README.md)：行为改动**先改文档并单独提交**，再写测试，最后才改实现。

---

## [1.1.0] — 2026-09-27

### 变更（触发语义）

- **`Caps` 按下即进入**模式（**不再**等 `hold_ms`，也不再经 `task()` 判定）；按下期间未按其它键就抬起 → **撤销**。
- **裸 `Caps` 单击无任何效果**（不再开关 vim）；**`Fn` 先按住 + `Caps` 单击 = 开关 vim**（vim 开关的唯一键盘入口）。
- `cfg->hold_ms` 不再用于 Caps（仅鼠标长按阈值仍在用）；契约改为 `cfg->fn_layer`。

### 修复（卡键/发错键，均为审计发现）

- **重入清理**：模式已激活时 `Caps` 再次按下，先反注册上一实例的全部键与 Ctrl，再进入——修掉
  "重复按下 Caps 导致宿主键永久卡住"。
- **过期 release 过滤**：模式内到达的 release 若不在本实例 held 表中，不反注册也不改 Ctrl 计数——
  修掉"模式前按住的键释放时提前松开 Ctrl"。
- **物理 Ctrl 中途松开**：清 `s_caps_phys_ctrl`，使后续非 F 键重新自注册 Ctrl——修掉"物理 Ctrl 松开后丢 Ctrl"。
- **层键豁免且放行**：模式内 QMK 层键不产生任何宿主键且不消费——修掉"按 Fn 发出 `Ctrl+低字节`"。
- **溢出吞吐一致**：held 表满时新键既不注册也不消费（不再出现无法反注册的卡键）。
- **孤立 release 守卫**：无 press 的 `Caps` release 无效果。

## [1.0.0] — 2026-09-27

### 新增

- **Caps 模式（鼠标模式同级的新键盘层模式，共享实现）**（触发语义见 [1.1.0]）：
  - 初始版本：长按 `Caps`（≥ `cfg->hold_ms`，默认 200ms）进入；短按为键盘既有语义。
    **该阈值触发已在 [1.1.0] 废弃**（现行：按下即进入）。
  - 模式内 `1`–`0`/`-`/`=` → `F1`–`F12`（**不带 Ctrl**）；**其余全部键** → `Ctrl+该键`
    （含 `Enter`/`Space`/`Tab`/`Backspace`/方向键/修饰键；修饰键按下即 `Ctrl+修饰`）。
  - **Ctrl 引用计数**：第一个非 F 键按下时按住、最后一个非 F 键松开时释放；F 键期间绝不按住 Ctrl；
    进入时物理已按住 Ctrl 则不重复注册、退出也不反注册。
  - 松开 `Caps` 退出：反注册本模式注册过的**全部**键与 Ctrl（含仍被按住的键），**防卡键**。
  - **不改变 vim 开关/模式**；vim 关闭时同样可用；模式内按键不进入 myfn/鼠标/Esc/快捷键/引擎。

### 相对"长按 Caps = 临时 Normal"的差异（行为变更）

- 旧行为（Caps 长按临时进入 Normal、松手恢复原模式）**已移除**；进入 Normal 现在**只由 `Esc`** 负责。
- 旧实现位于共享 keymap 层的 Caps tap/hold 状态机；新行为同样在该处，但**判定与映射集中在 Caps 模块**。

### 已知取舍（见 [`readme.md`](readme.md) §4）

- `Ctrl+M`=Enter、`Ctrl+I`=Tab、`Ctrl+H`=Backspace、`Ctrl+[`=Esc 等宿主别名冲突由使用者承担。
- 取键按 QMK 基础键码，包装修饰（`LSFT(...)` 等）在模式内被忽略。
