# Caps 长按模块（Caps mode）

> **定位**：与具体键盘无关的**键盘层模式规格** —— 规定「按住 `Caps` 时，各个键发出什么」。
> 本目录是 Caps 模块的**唯一权威**（架构与判据见 [`design.md`](design.md)，目标行为见 [`readme.md`](readme.md)，
> 版本与缺陷见 [`changes.md`](changes.md)，用例见 [`testcase.md`](testcase.md)）。
> 注：文中出现的键盘名（如 QK61/NUT65）仅为**参考示例**；共享层不含任何键盘专属实现或测试。

---

## 1. 定位与范围

- Caps 模式是**键盘层模式**：与鼠标模式（MOUSE）同级，**引擎不参与**——模式内所有键由本层直接翻译后发往宿主。
- **触发即生效**：按下 `Caps` 的那一刻就进入模式（不等 `hold_ms`），因此"按下 Caps 后立刻按 1"必然发出 `F1`；
  代价是一次**未按任何其它键**的快速按抬会短暂进入模式再撤销（见 §3 的撤销规则）。
- **共享实现**：两键盘共用同一份实现，键盘侧**零代码接入**（只需 `cfg->fn_layer` 识别 `Fn`+`Caps`
  + 既有 `Caps` 键位；`hold_ms` 自 1.1.0 起**只用于鼠标模式**的长按阈值，不再用于 Caps）。
- **与 vim 无关**：vim 开启或关闭都能用；模式内的键**不喂引擎**，vim 的开关/模式在模式期间**完全不变**。
- **状态边界**：模式期间只维护「本模式注册过的键」这张有界表；退出即清空。关机/复位后不保留任何状态（默认关闭）。

## 2. 触发与退出

| 事件 | 行为 |
| :--- | :--- |
| `Caps` **按下**（**无需等待** `hold_ms`） | **立即进入** Caps 模式；随之按下的键已按本模式映射 |
| `Caps` 按下期间**未按任何其它键**就抬起 | **撤销本次进入**（不误发键、不改 vim 状态）；即"短按"无任何效果 |
| `Caps` 按下期间**按过其它键**再抬起 | 正常退出模式（那些键按本模式映射已发出） |
| **`Fn` 先按住** + `Caps` 单击 | **切换 vim 开/关**（vim 开关的唯一键盘入口）；`Fn` 后按 Caps 不会进模式 |
| `Caps` 单击（**裸按**，无 `Fn`） | **无任何效果**（不开/关 vim，也不进入 Normal） |
| 模式期间任意按键的 press/release | 由本模块接管（见 §3），不进入 myfn/鼠标/Esc/快捷键/引擎等后续环节 |

> 进入模式的 `Caps` 按下本身被本层消费（不会漏出 Caps Lock）；模式内 `Caps` 的抬起用于退出，也不会漏出。

## 3. 键映射

| 物理键 | 发出 |
| :--- | :--- |
| `1` `2` `3` `4` `5` `6` `7` `8` `9` `0` `-` `=` | `F1` `F2` `F3` `F4` `F5` `F6` `F7` `F8` `F9` `F10` `F11` `F12`（**不带 Ctrl，Ctrl 也不按住**） |
| **其余全部键**（含字母/数字以外的符号、`Enter`/`Space`/`Tab`/`Backspace`/方向键/修饰键等） | **`Ctrl` + 该键**；修饰键按下即 `Ctrl+该修饰`（如 `Shift` → `Ctrl+Shift`） |

**Ctrl 的按住规则（引用计数）**：

- 模式内**第一个非 F 键**按下时按住 Ctrl；
- **最后一个非 F 键**松开时释放 Ctrl（因此重叠按多个非 F 键时 Ctrl 一直按住，可当组合键的修饰用）；
- **F 键自身不碰 Ctrl**（design §4 不变量 1）：按键路径既不注册 Ctrl、也不改变引用计数。**例外**：若按下
  F 键时**仍有非 F 键按住**（本模块的合成 Ctrl 仍在位），或进入模式时/模式内按住了物理 Ctrl，F 键会与
  已按住的 **Ctrl（合成或物理）** 叠加成 `Ctrl+F1`…；F 键自身的按下/抬起不会卸掉该 Ctrl。
- 模式内按物理 `Ctrl`（左/右）时：本模块**不注册合成 Ctrl**，由真实修饰键承担；其按下/抬起**两沿都交回 QMK**
  （避免吞掉释放导致位卡住）。

## 4. 已知取舍（由使用者承担）

- **宿主别名冲突**：`Ctrl+M`=Enter、`Ctrl+I`=Tab、`Ctrl+H`=Backspace、`Ctrl+[`=Esc 等；
  这是「其余键一律 `Ctrl+`」的直接后果。
- **包装修饰被忽略**：取键使用 QMK 基础键码，`LSFT(...)` 之类的包装修饰在模式内不生效，
  统一按「`Ctrl+基础键`」发出。
- **非基础键码豁免**：自定义键/厂商键（`0x7E00+`，如 `VIM_MOUSE`、`QK_BAT`）**不参与**模式映射，
  原样交回 QMK（与层键同规则）——它们的低字节不是键位语义。
- **与其它键盘层功能的先后**：Caps 模式的拦截**先于** myfn 骨架、鼠标状态机、`Shift+Esc`、Esc 切换、
  §2.1 快捷键表与引擎，因此模式内 `Esc` 发 `Ctrl+Esc`，不会触发 vim 的 Esc 切换语义。
