## 1. `KV_EMIT_GAP_MS = 1`（1 键/ms 节流）：高计数命令与连续快速两条命令

- **编号**：A1（对应 [`engineering-spec.md`](engineering-spec.md) §4「残余角落」与 §7.7）
- **要验证什么**：
  1. 真实宿主是否接受 **1 键/ms** 的连续键码（不丢键、不粘键）；
  2. 四条**高计数命令**（`99dd`、`99J`、`>99j`、`v99w`）是否**整条完整执行**，尤其最后一个
     真正改文档的键（`Ctrl+X`/`Ctrl+V`/`Tab`）不被丢掉；
  3. 前一条大命令的队列**尚未排空**时连按第二条大命令，第二条是否仍完整执行（§4.3 的
     「已知残余」：`pending ≥ 248` 时 room 不足仍按"重复数取 1"发键，可能把队列顶到
     `EMIT_CAP = 256`，`push` 静默丢**尾部键**）。
- **前置条件**：vim 开；`/tmp/kv-120.txt` 已生成；宿主 A（编辑器）设置 `:set noexpandtab`
  （便于用 Tab 观察缩进）；每条命令前重新载入文件或按 `u` 还原。
- **引擎单命令键码数（本仓库探针实测，2026-10-01）**：`99dd` = **103**、`99J` = **248**、
  `>99j` = **105**、`v99w` = **250**（单命令上界，预算法定上限 250）。即 1 键/ms 下
  `99J` 持续发键约 248 ms、`v99w` 约 250 ms。
- **操作步骤**：
  1. 载入 `/tmp/kv-120.txt`，`gg` 回第 1 行。
  2. 逐条执行并记录：`99dd`、`99J`、`>99j`、`v99w` 后接 `d`（每条前还原文件）。
  3. **连发**：`gg99J` 后**立刻**（不等待，< 0.2 s，即上一条还在发键）再按 `99dd`；
     以及 `gg99dd` 后立刻再按 `99dd`。
  4. 在 **NUT65 无线模式**下把步骤 2–3 重做一遍（无线吞吐更低，更易暴露）。
- **预期结果**（均与 vim.tiny 实测逐字节一致）：
  | 命令 | 缓冲区 | 光标/其它 |
  | :--- | :--- | :--- |
  | `gg99dd` | 余 **21** 行，首行 `L100 aaa bbb ccc ddd`，末行 `L120 aaa bbb ccc ddd` | 光标在 `L100` 行首；无残留选区 |
  | `gg99J` | 余 **22** 行；首行 = `L001…L099` 以**单空格**连接成一行；第 2 行起 `L100 …` | 无残留选区 |
  | `gg>99j` | 仍 **120** 行；`L001–L100` 各多**一个缩进**（Tab）；`L101–L120` **不变** | 光标回 `L001` 行首 |
  | `ggv99wd` | 余 **101** 行；首行**恰为 `dd`**，第 2 行 `L021 aaa bbb ccc ddd` | —— |
  | `gg99J` → 立刻 `99dd` | 缓冲区**为空**（0 字节） | 第二条命令必须完整删除，不得只删一部分 |
  | `gg99dd` → 立刻 `99dd` | 缓冲区**为空**（0 字节） | 同上 |
  - 任何一步若出现"少删了几行 / 少连了几行 / 缩进只做了一半 / 高亮选区残留 / 行尾少了换行"，
    都判 `不符`。
  - 无丢键的判定辅助：真实 Vim 里再跑同一条命令，比对 `wc -l` 与 `wc -c`（上表数字即基准）。
- **若不符说明什么风险**：说明 §4.3 的「已知残余」在真机上**可达**——队列被预填到
  `pending ≥ 248` 时仍按"至少发 1 次"补齐，把队列顶到 256，`emit.c` 的 `push` 静默丢弃
  **命令尾部装饰键**；轻则光标/选区残留（下一个按键替换选区 = **数据损坏**），重则范围已选中
  却发不出改文档键 = **半截命令**。若只在无线模式不符，属宿主/链路吞吐问题，应在两键盘
  readme 登记"无线模式下建议放慢大计数命令"。

## 2. 右 Shift 懒发送（lazy send）

- **编号**：A2（对应 `vim/readme.md` §9b 注、`vim/design.md` §4.12 右 Shift 段落、
  [`engineering-spec.md`](engineering-spec.md) §7.1）
- **要验证什么**：vim 开启时**孤立**右 Shift 是否在宿主上完全不产生事件（不触发 IME/输入法切换）；
  右 Shift 与其它键同按时是否临时补**左 Shift**、且任何松键顺序都不留下卡住的 Shift。
- **前置条件**：vim 开；宿主 A + 宿主 B；一个已启用的输入法（fcitx5 拼音 / macOS 拼音）；
  一个能显示本次按键的页面（如键盘查看器网页）用于确认"没有 Shift 事件"。
- **操作步骤**：
  1. 单独按右 Shift 再抬起（不碰其它键），重复 20 次 → 观察输入法是否切换、宿主是否收到 Shift。
  2. 右 Shift 按住 + `a` → 应为 `A`；分别用两种松键顺序各做 5 次：
     ① 先松 `a` 再松右 Shift；② 先松右 Shift 再松 `a`。之后立刻继续打 `bbb`，观察是否变大写。
  3. 右 Shift + `Ctrl+C`（在宿主 B 终端里，应形成 `Ctrl+Shift+C` 的复制语义）。
  4. 右 Shift + 符号键（如 `1`、`-`）、右 Shift + 方向键各试一次。
  5. 切到 `Fn`+`Caps` **关闭** vim，再单独按右 Shift 5 次 → 应恢复成普通右 Shift（宿主正常收到 Shift）。
- **预期结果**：
  - 步骤 1：宿主**零事件**、输入法**不切换**（这是懒发送存在的唯一理由）；
  - 步骤 2：`右Shift+a` = `A`；两种松键顺序之后都不会"卡大写"（`bbb` 必须是 `bbb` 而不是 `BBB`）；
  - 步骤 3：形成 `Ctrl+Shift+C`；步骤 4：符号键/方向键按各宿主预期组合；
  - 步骤 5：vim 关闭后右 Shift 与普通键盘完全一致（单独按也发 Shift）。
- **若不符说明什么风险**：若孤立右 Shift 仍触发输入法切换 → IME 被误切、输入丢失（本项的直接目的失效）；
  若补左 Shift 的注册/反注册与真实修饰键状态冲突 → **左 Shift 卡住**，之后所有字母都变大写/组合键，
  属"输入被劫持"级事故；若只在某个 OS/IME 不符，必须在两键盘 readme 里登记为宿主相关限制，
  而不是笼统写"已支持"。
- **结果栏**：☐ 通过　☐ 不符　　备注：________________

## 3. Caps 模式合成 Ctrl 与**物理** Ctrl 的交错

- **编号**：A3（对应 `caps/readme.md` §3「Ctrl 的按住规则」、`caps/design.md` §2/§4、
  `engine/test/glue/test_rgb.c: test_caps_ctrl_bitmodel`、
  [`engineering-spec.md`](engineering-spec.md) §7.2）
- **要验证什么**：Caps 模式内**合成 Ctrl**（引用计数）与**物理**左/右 Ctrl 的按/抬交错组合，
  在真实宿主上是否产生正确的 `Ctrl+键`；`测试套件只覆盖了位模型`，本项补真实宿主观感与卡键。
- **前置条件**：键盘 + 宿主能显示收到的组合键（键盘查看器网页 / VSCode 快捷键面板 / 终端）；
  Caps 模式已可用（**按下 Caps 即进入**，松开退出）。
- **操作步骤**（每步都记录宿主实际收到什么）：
  1. 按住 Caps → 按 `c` → 松 `c` → 松 Caps：应只看到 `Ctrl+C`（且 Caps 本身不产生 CapsLock）。
  2. 模式内**同时**按住 `c` 和 `v`（两个非 F 键重叠），先后松开：观察 Ctrl 是否全程按住、是否到
     最后一个非 F 键抬起才释放。
  3. 模式内**先按物理左 Ctrl**，再按 `c`；先松物理 Ctrl、此时仍按住 `c`，再按 `v`
     （验证"物理 Ctrl 中途松开后，下一个非 F 键重新自注册 Ctrl"）。
  4. 模式内**先按 `c`**（合成 Ctrl 已在位）再按**物理左 Ctrl**，然后松物理 Ctrl
     （验证不得卸掉物理位）；换**右 Ctrl**重做一遍（逐位判断）。
  5. 模式内按 `1`…`0`（= `F1`…`F12`）的同时另一只手按住物理 Ctrl → 应为 `Ctrl+F1`…；
     确认 F 键自身不改变 Ctrl 引用计数（松 F 键后 Ctrl 仍按住）。
  6. 模式内按住 `c` 的同时松开 Caps 退出模式（以及"未按其它键就抬起 Caps"的撤销路径各一次）→
     松手后立刻在宿主里打 `abc`，确认没有 Ctrl 卡住（不会变成全选/快捷键）。
- **预期结果**：合成 Ctrl 与物理 Ctrl 叠加为**一个** Ctrl 语义；全程不出现"缺 Ctrl"（该发组合键却
  发了裸键）或"多 Ctrl"（普通字母被当 `Ctrl+字母`）；退出模式后宿主修饰位归零（`abc` 就是 `abc`）。
  逐位/引用计数的**逻辑**已由主机套件覆盖，本项只需确认真机与位模型一致。
- **若不符说明什么风险**：`register_code` 无引用计数、LCTL/RCTL 是不同 bit；真机/宿主状态机一旦与
  位模型不一致 → 要么 **Ctrl 永久卡住**（整个键盘变成快捷键发射器，必须拔插恢复），要么组合键失灵。
  `caps/design.md` §2 已记录过"提前释放仍被其它键需要的 Ctrl"与"卸掉物理按住的 Ctrl"两类 P0 缺陷，
  本项就是它们在真机上的最后一道门。
- **结果栏**：☐ 通过　☐ 不符　　备注：________________

## 4. 宿主对 `Shift+↓` 的**列保持**（引擎的行选依赖它）

- **编号**：A4（对应 `vim/design.md` §1/§4.8 行选实现、
  [`engineering-spec.md`](engineering-spec.md) §7.3）
- **要验证什么**：宿主在 `Shift+↓` 时是否保持**期望列**（desired column），使引擎的
  `Home×2 + Shift+Down×n` 能覆盖**整行**——`Ndd`/`Nyy`/`N>>` 全部依赖这一宿主行为。
- **前置条件**：vim 开；三个宿主各一份：宿主 A（GUI 编辑器）、宿主 B（终端里用 `vim.tiny` 打开
  同一文件）、宿主 C（浏览器输入框）；参考文件含**长短不一的行**：
  ```sh
  printf 'AAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nBB\nCC\nDDDDDDDDDDDDDDDDDDDD\n' > /tmp/kv-collines.txt
  ```
- **操作步骤**：
  1. 在宿主 A 打开 `/tmp/kv-collines.txt`，光标放第 1 行第 1 列；按 `Shift+↓` 两次 → 观察高亮
     是否覆盖第 1–2 行**整行**（第 2 行只有 `BB`，活动端停在哪里？是否越到第 3 行？）。
  2. 把光标放到第 1 行第 20 列后 `Home` 再 `Shift+↓` → 同一观察。
  3. 真机执行 `2dd`、`u`、`2yy`、`2>>`，与 `vim.tiny` 同命令逐项比对（缓冲区行数/内容、无名寄存器、
     光标）。
  4. 对"短行在上、长行在下"（第 2–3 行）与"长行在上、短行在下"（第 1–2 行）两种排布各做一遍。
  5. 在宿主 B、宿主 C 上重复步骤 1–2（只做观察即可，判定宿主是否保持列）。
- **预期结果**：`Home` 后列为 0，`Shift+↓` 后选区扩到下一行**同列**（列 0）⇒ 整行；短行被夹取到
  行尾也不跨行。因此 `2dd` 精确删除第 1–2 行（余 2 行）、`2yy` 复制 2 整行、`2>>` 缩进 2 整行，
  与 vim.tiny 一致，且无残留高亮。
- **若不符说明什么风险**：宿主若**重置列**或把选区停在任意列，半开选区只覆盖行的一部分：
  `Ctrl+X` 会剪掉半行（**缓冲区损坏**）、`yy` 只复制片段、`N>>` 只缩进半行。这是"宿主相关性"风险，
  不符就按宿主逐个登记到两键盘 readme（"已验证宿主 / 不支持的宿主"），不能笼统写"支持"。
- **结果栏**：☐ 通过　☐ 不符　　备注：________________

## 5. `Ctrl+C` 复制后宿主是否**保留选区**（引擎依赖它补 `Esc`）

- **编号**：A5（对应 `vim/design.md` §4.8 `yy`/`Y` 与 §4.9「`Esc` 收尾」：
  "宿主在 `Ctrl+C` 后通常保留高亮选区，不取消则下一个按键会替换刚复制的行"）
- **要验证什么**：宿主 `Ctrl+C` 后是否保留高亮选区；引擎在 `y`/`yy`/行选动作后补发的 `Esc`
  是否恰好清掉它、且**没有副作用**（例如 Esc 被宿主/终端吃掉后干了别的事）。
- **前置条件**：vim 开；宿主 A + 宿主 B；一个能观察高亮与"下一个按键是否替换选区"的编辑缓冲区。
- **操作步骤**：
  1. 用鼠标（或 `Shift+方向`）选一段文本 → `Ctrl+C` → 观察选区是否仍高亮。
  2. 紧接着按一个字母键 → 观察是否**整段替换**（证明"保留选区"确实存在、必须清）。
  3. 真机执行 `yy`：观察复制后高亮是否被取消、缓冲区不变；随后按 `p` 应粘贴**整行**而不是替换。
  4. 真机执行 `ylp`、`yyp`、`vly`（字符/行两条路径各一），与 vim.tiny 同命令比对缓冲区。
  5. 在"宿主正弹着补全菜单/查找框"时按 `yy`（Esc 会被宿主抢走的场景）观察是否有额外副作用。
- **预期结果**：步骤 1 宿主**保留**高亮（这正是引擎补 `Esc` 的理由）；步骤 2 字母键替换整段；
  步骤 3 引擎的 `Esc` 让高亮消失、`p` 粘整行；步骤 4 缓冲区与 vim.tiny 一致（寄存器类型：
  `dd`/`yy`/`Y`/行选 = 行级；`x`/`X`/`s`/`dw`/`yl`… = 字符级，见 `design.md` §4.8）。
- **若不符说明什么风险**：若宿主保留选区但 `Esc` 清不掉（扩展/弹窗抢键），下一个按键会**替换刚复制的
  整行** = 数据损坏；若 `Esc` 在宿主里另有语义（关弹窗、退全屏、被 shell 或远端程序吃掉），补发的
  `Esc` 会产生额外副作用；若宿主**不**保留选区，补发的 `Esc` 通常无害，但必须在 readme 里登记该宿主
  的实际行为，避免"以为靠 Esc 兜底"的错误假设。
- **结果栏**：☐ 通过　☐ 不符　　备注：________________

## 6. **末行无尾换行**的缓冲区表现

- **编号**：A6（对应 `vim/design.md` §4.9 ③/⑩ 与 §4.8 `dd` 的 `Shift+→`：
  "末行无换行时 `→` 夹取到缓冲末尾，故 `Shift+Right` 无效"）

## 7. 3 秒 `Esc` 宽限（grace）的实际手感

- **编号**：A7（对应 `vim/readme.md` §1/§10、`vim/design.md` §4.12 **与 §4.13**、
  `VIM_ESC_GRACE_MS = 3000`、`VIM_ESC_HOLD_MS = 200`）
- **要验证什么**：`Normal` 空闲按 `Esc` 回到 `Insert` 后 **3 秒**内：① 模式色变**橙**
  （`#FF8000`）；② 再按 `Esc` 仍是**真实 Esc** 且重置计时；③ 3 秒后回 Insert 绿、`Esc` 恢复
  「Insert→Normal」切换语义；④ 长时间使用不出现「假亮橙」（16 位回绕 P1 的真机回归）；
  ⑤ **长按 Esc ≥200 ms（§4.13 新功能）**：窗口内**直接进 Normal 且宿主零输出**，短按行为不变。
- **前置条件**：vim 开；RGB 可见；宿主 B（终端或全屏程序），使真实 `Esc` 有肉眼可见效果
  （如退出全屏、清掉 shell 提示）；秒表。
- **操作步骤**：
  1. 按 `Esc` 进 Normal（蓝）；再按 `Esc` → 应回 Insert 且宿主收到**真实 Esc**，灯变**橙**。
  2. 1 秒内再按 `Esc` → 仍是真实 Esc、灯保持橙；再等 3 秒，灯才回绿。
  3. 等灯回绿后按 `Esc` → 变蓝（Normal），宿主**不应**收到 Esc。
  4. 连续快速按 `Esc` 5 次：第 1 次进 Normal、第 2 次回 Insert 并发 Esc 且亮橙、第 3–5 次在窗口内
     都发真实 Esc 并保持橙。
  5. 连续打字/操作 > 70 秒（跨过 65536 ms 回绕点）后观察灯是否**假亮橙**；同时确认宽限窗口不会
     在未按 `Esc` 的情况下被开启。
  6. 用其它进入 Insert 的路径（`i`/`a`/`o`、`Fn`+`Caps` 开启 vim）确认**不亮橙**。
  7. **长按测试**：按 `Esc` 进 Normal（蓝）→ 再按 `Esc` 回 Insert 且亮橙（窗口已开）→ 在窗口内
     **按住 `Esc` 约 0.5 秒再松** ⇒ 应**立刻**变蓝（Normal），且宿主**没有**收到任何 Esc。
  8. **短按对照**：在同一窗口内**快速点按** `Esc`（明显短于 0.2 秒）⇒ 宿主**应**收到真实 Esc，
     灯保持橙、窗口续期（与从前一致）。
  9. **无窗口对照**：等窗口过期（灯回绿）后按 `Esc` ⇒ 立即变蓝（Normal），**不得**出现可感的延迟
     （该路径不等待长按判定）。
- **预期结果**：橙色窗口 = 3 秒（秒表粗测误差 ≤0.3 s）；窗口内**短按** `Esc` 一律真实透传且续期；
  窗口过期后 `Esc` 恢复切换语义；步骤 5 不得出现假橙；步骤 6 一律保持 Insert 绿；
  **步骤 7**：长按在窗口内也进 Normal、宿主零输出（这是 §4.13 的核心，宿主多收到一次 Esc 即为不符）；
  **步骤 8**：短按仍能送出真 Esc（短按被长按判定吃掉即为不符）；**步骤 9**：无窗口时无额外延迟。
- **若不符说明什么风险**：窗口过短/过长 → 连续退出全屏/多层菜单的操作失效或误切模式；
  真机不亮橙 → 键盘侧 RGB 接入或 `timer_read32` 路径与共享层不一致（`qmk/README.md` §6 坑位 6
  正是「16 位计时回绕让已过期窗口复活」，实测每 65.5 s 假命中 3 s）；假橙会让用户误以为处于
  Normal→Insert 过渡态。**长按相关**：长按不生效 ⇒ 窗口内仍无法立刻回 Normal（本功能白做）；
  长按误触发 ⇒ 想连发真 Esc（如退出多层菜单）时被切成 Normal；**短按被吃掉** ⇒ 终端/程序收不到
  需要的真 Esc（最严重，因为用户看不见）；已知取舍：把 Esc 当作 **Meta 前缀**按住再按字母的用法
  会改为进 Normal —— 这是长按语义的固有代价，若你的用法依赖它，请在此记录并回报。

- **若不符说明什么风险**：刷错键盘或旧版本而不知情（版本块缺"上一版"、tag 未 push 就刷）；
