# 变更记录 — qmk-myfn

本库所有重要改动记录于此。格式参考 [Keep a Changelog](https://keepachangelog.com/)，
版本遵循语义化版本。

---

## [1.3.0] — 2026-09-21

### 变更（规则收紧）
- **myfn 层「未定义键」由"透传"改为"吞键"（含修饰键）**：避免 `Fn+Shift+Esc` 之类组合泄漏（修饰键放行等于没避免）。
  - §3 表末行、§4 规则 3、§5 约束、§6 示例（`default`）同步。
  - **唯一例外**：原厂 Fn+bootloader 组合键在吞键前用**独立物理修饰键影子**判断（不依赖 `get_mods()`），故吞修饰键不影响它。

---

## [1.2.0] — 2026-09-21

### 新增（底排约定）
- 新增「Space 右侧（**非方向键**）从左到右 = `Alt` `Fn` `Menu` `Ctrl`」约定：
  `Menu` 仅当右侧共 **4** 个键位时存在，`Ctrl` 当右侧 **≥3** 个键位时存在；
  键数只统计非方向键，**原生方向键位不动**。
- **Mac base 同理**：`Alt` 位对应 Mac 的 `Cmd`（`KC_RCMD` / `MOD_RGUI`）。
- 采用此约定后绝大多数键盘无需调整物理键位。

---

## [1.1.0] — 2026-09-20

### 新增（休眠 / 唤醒约定）
- 新增 `Fn+L = 休眠`（**短按**；前置：键盘无物理切换按键、非 USB 有线；不满足 → 空跑）。
- 新增 `Fn+右上角键 = 唤醒`（右上角键按布局定，如 `Delete` / `Backspace`，**不可替换**；
  仅该组合真正唤醒，其它键仅瞬时唤醒 MCU 后自动重回深睡）。
- 不改 §2 最高优先级约束与其它键位。

## [1.0.0] — 2026-09-19（V1.0 冻结）

### 变更（键位调整 + 最高优先级约束）
- **新增最高优先级约束**：键盘**必须保留厂商原厂进入 bootloader（刷固件 / DFU）模式的 Fn 组合键**；
  其优先级高于本约定的一切键位映射，冲突时以该组合键为准。（`readme.md` 新增「§2 最高优先级约束」，后续小节顺延重编号。）
- **F 区与音量调整**：
  - `Fn+1..0`：`F1..F10`（不变）
  - `Fn+-` / `Fn+=`：**改为 `F11` / `F12`**（原为音量）
  - `Fn+[` / `Fn+]`：**新增 音量减 / 音量增**

### 变更（取消代码机制，转为纯文档/约定）
- **删除代码**：移除 `src/myfn.c`、`src/myfn.h`、`rules.mk`。本仓库不再提供可编译的库。
- **定位**：仓库只提供 **myfn 约定** —— 一份与具体键盘无关的规则说明；是否遵守由各键盘自行实现。
- **约定表**：
  - Fn+1 / 2 / … / 0：F1 / F2 / … / F10（无前置）
  - Fn+`-` / Fn+`=`：F11 / F12（无前置）
  - Fn+`[` / Fn+`]`：音量减 / 音量增（无前置）
  - Fn+Q / W / E：蓝牙 1 / 2 / 3（支持蓝牙；有物理开关须在蓝牙挡）
  - Fn+R：2.4G（支持 2.4G；有物理开关须在 2.4G 挡）
  - Fn+T：切有线（键盘无物理切换按键；有物理开关 → 空跑）
  - Fn+Space：电量（有电池）
  - Fn+Esc：初始化配置（无前置）
  - Fn+Caps：退出 / 开关 Vim（键盘实现了 Vim）
  - 其余键：透传
- **三条规则**：前置条件满足 → 执行；不满足 → 不执行（吞键/空跑）；未在表中声明 → 透传。
- **约束**：键盘必须把 Fn 键改成 myfn 键；键盘只实现自己能实现的功能。
- `readme.md` 全量重写为上述约定（含通用实现示例），不含任何具体键盘内容。
- 此前未发布的库实现与相关改动随代码一并撤销。

## [0.1.0] — 2026-09-19

首个版本，配合 QK61 / NUT65 的「新 Fn 层」需求。

### 新增

- **目录与工程文件**
  - `src/myfn.h`、`src/myfn.c`
  - `rules.mk`（提示通过 `SRC += qmk-myfn/src/myfn.c` 接入）
  - `readme.md`（完整中文文档）
  - `changes.md`（本文件）
  - `LICENSE`（MIT）

- **编译期宏**
  - `MYFN_LAYER`：新 Fn 层层号。**无默认值**，未定义时 `#error`，避免层号冲突 / 误覆盖。
  - `MYFN_BATTERY_KEY`：电量触发键，默认 `KC_SPC`。

- **运行时 API**
  - `bool myfn_active(void)`：当 `MYFN_LAYER` 激活时返回真。
  - `bool process_record_myfn(uint16_t keycode, keyrecord_t *record)`：
    在 Fn 层激活时拦截 `MYFN_BATTERY_KEY`，调用 `myfn_battery()` 并消费该事件。

- **强符号接线**
  - `layer_state_set_user()`：库提供强符号实现，层变化时转调 `myfn_fn_status()`，
    键盘无需自己写。若 keymap 需要自定义该函数，必须自行调用
    `myfn_fn_status(myfn_active())`（在该库已随 1.0.0 移除前，这一接线由库负责）。

- **弱「父类」占位（键盘覆盖）**
  - `void myfn_fn_status(bool on)`：默认空实现，键盘用于维护自身 Fn 标志
    （QK61 的 `Key_Fn_Status`）。
  - `void myfn_battery(bool pressed)`：默认空实现，键盘提供真正的电量显示逻辑；
    没有电量功能的键盘留空即可（空跑）。

### 设计说明

- 库是**通用**的；新 Fn 层的**内容**（音量 / 无线 / 其它）保留在各键盘 keymap，
  因为布局宏与无线键码因键盘而异。
- 不依赖网络，不依赖 QMK module 系统；纯 `SRC +=` 引入。
- 与 `qmk-vim` 同构：弱钩子 + 键盘覆盖，多分支以子模块指向同一 commit。

### 已知事项

- 新增层后需同步 `DYNAMIC_KEYMAP_LAYER_COUNT`（启用 VIA 时），否则触发 QMK 静态断言。
- 若同一 keymap 需要自己的 `layer_state_set_user()`，会与库的强符号冲突；此时应改为**在自定义实现内显式调用** `myfn_fn_status(myfn_active())` 以转发 Fn 状态（该库已随 1.0.0 移除，此条为历史说明）。
