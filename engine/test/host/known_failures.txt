# engine/test/host/known_failures.txt — RATCHET baseline for `make matrix-test`.
#
# Format:  <case-name> <failing-dimensions>     e.g.  "yyp cur" or "dw buf+reg"
# Dimensions are `buf` (buffer content), `reg` (unnamed register) and `cur`
# (cursor).  A case listed here is a KNOWN mismatch against real Vim that is not
# yet resolved; each is one of:
#   (a) a deviation already declared in vim/design.md §4.4/§4.9 or vim/readme.md
#       that has not been individually cited in matrix.py's XFAIL table yet
#       (the preferred long-term home for these), or
#   (b) an inherent limitation of a pure-keycode layer — the engine cannot read
#       the buffer, so it cannot know line/column boundaries or buffer length, or
#   (c) a real defect that is still open.
#
# The gate stays useful because this is a RATCHET:
#   * a mismatch whose case is NOT here                  -> hard failure
#   * a listed case failing on a dimension NOT listed    -> hard failure
#     (so a NEW kind of corruption inside a known-broken case is still caught)
#   * a listed case that now matches real Vim entirely   -> hard failure (prune)
#   * an XFAIL entry that now matches real Vim           -> hard failure (prune)
# So this file may only ever shrink or lose dimensions. Do NOT add a name here to
# silence a mismatch you have not understood; cite it in matrix.py's XFAIL table.
#
# Run `cd engine && make matrix-test` (or `python3 test/host/matrix.py --all`
# for per-case detail) to see the current split.
