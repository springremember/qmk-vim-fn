# 键盘迁移计划：qmk-vim V1.0 → qmk-vim-fn（先 QK61，后 NUT65）

> 注：本文档为项目记录（含具体键盘名 QK61/NUT65 等），仅供参考；不属于共享层（`engine/`+`qmk/`）规范。

> 目标：把 NUT65 / QK61 两块键盘从「qmk-vim V1.0 子模块 + keymap 内联 myfn」迁移到统一的
> **qmk-vim-fn**（合并引擎 + myfn 约定），行为遵循 `qmk-vim-fn/vim/design.md`、`vim/readme.md`、
> `fn/readme.md`。
>
> 约束：在**现有分支**（`nut65` / `qk61`）上做，不开新分支；V1.0 靠 tag + 固件留档保护；
> 源仓库 `qmk-vim` / `qmk-myfn` 不再改。

## 0.1 底排约定（Space 右侧）

**从左到右依次为 `Alt`、`Fn`、`Menu`、`Ctrl`**；`Menu` 仅当右侧共 **4** 个键位时存在，`Ctrl` 当右侧 **≥3** 个键位时存在：

| 右侧（非方向键）数 | 从左到右 |
|---|---|
| 2 | `Alt` `Fn` |
| 3 | `Alt` `Fn` `Ctrl` |
| 4 | `Alt` `Fn` `Menu` `Ctrl` |

> 采用此约定后，**绝大多数键盘无需调整物理键位**；仅个别键盘需按上表对齐逻辑键码。
> 键数**只统计非方向键**；含**原生方向键**的键盘，方向键位不动，本约定只约束"非方向键"。右 `Shift` 通常在上一行，不计入。
> **Mac base 同理**：其中 `Alt` 位对应 Mac 的 `Cmd`（`KC_RCMD` / `MOD_RGUI`）。

## 1. 通用删除项（两键盘）

- 子模块 `qmk-vim` → `qmk-vim-fn`；`rules.mk`（现状是**逐文件** `SRC += qmk-vim/src/*.c`）改为「**engine 源 + 独立 glue 源**」
  （`engine/` 与 QMK 解耦，源清单见 `design.md` §4.6；glue 与共享 keymap 层见 `design.md` §4.12——
  `qmk/vim_glue.{h,c}` 与 `qmk/vim_keymap_common.{h,c}` 由子模块统一提供，keymap 只给 cfg 实例；
  **排除 `engine/Makefile`**，其仅用于主机测试）。
- `config.h` 删**全部 qmk-vim 特性开关**：`VIM_*` **以及 `BETTER_VISUAL_MODE`**（`VIM_LED_INDEX` 见下另议）。
- **include 调整**：删 `#include "qmk-vim/src/{vim,modes,actions,process_func}.h"`，改为 `kv.h` + glue 头；清理 `extern process_func_t process_func` 与各弱钩子的外部声明。
- 删除旧机制：
  - 弱钩子 `normal_mode_user` / `insert_mode_user` / `visual_mode_user` / `visual_line_mode_user` / `process_*_mode_user`。
  - replace：`process_replace_mode` / `enter_replace_mode` / `replace_active`（`R`/`Shift+R` 透传）。
  - `vim_extra_undos`（dd 不再自动双撤销）。
  - `motion_counter` 的 keymap 侧 extern 清理。
  - `Shift+J`（join 交引擎）。
  - 文本对象相关（引擎已剔除）。
  - **`alt_tab_held`（NUT65）与 `Tab` 的显式透传（QK61）**：`Tab` 交给「非 vim 键码一律透传」。
- **键盘侧旧状态变量（成批清理/改造）**：
  - 通用：`esc_swallow_release`、`esc_press_timer`（Esc 去长按后作废）、`replace_active`。
  - QK61：`menu_*`、`ent_ms_pressed`、`spc_ms_pressed`、`ms_move_held`、`spc_press_timer`、`spc_holding`、`ent_press_timer`；`fn_esc_swallow` 与 `reset_armed/reset_fired/reset_timer` **保留/改名**（Fn+Esc 3s reset 仍需吞按下+抬起，覆盖"先松 Fn"边界）；`shift_combo_kc` **保留**（Shift+Esc 仅 Insert 的 release 吞键配套）。
  - NUT65：`spc_press_timer`、`spc_holding`、`arrow_l/arrow_r/arrow_combo`、`rc_held/rc_timer`、`alt_tab_held`。
  - **保留**（Caps 行为需要）：`caps_press_timer`、`caps_was_insert`。
- 其他：`config.h` 的 `VIM_LED_INDEX`（死宏，可删）；`encoder_map`（音量旋钮）保留。
- **`Shift+Esc`（仅 Insert）**：① 现两键盘 `pr_shift_combos` 是**任意模式**命中 → 改为仅 Insert（对齐 `vim/readme.md` §9）；② **两键盘都补 release 吞键**（`shift_combo_kc` 机制；NUT65 现缺——先松 Shift 会漏一个真 Esc）。
- **Fn 层未定义的键（含修饰键）一律吞键**（`fn/readme` 1.3.0），分三类处理：
  - **未声明**位 → `KC_NO`（空跑）；
  - **已声明且 handler 依赖键码**（如 QK61 `_FN` 的 Space/Caps、NUT65 的 Caps）→ **保留 `_______`**（透明回落 base 的 `KC_SPC`/`KC_CAPS`，改 `KC_NO` 会破坏 handler）；NUT65 的 Space 已是 `HS_BATQ`，直接保留；
  - **已声明但本次有意不实现**（`Fn+L`/`Fn+右上角` 休眠/唤醒）→ 空跑：**QK61 由 `process_record_myfn` 吞键、NUT65 把 `_FN` 对应位映射 `KC_NO`**（两键盘机制不同，见 §2.3；均无 handler 依赖，安全）。
  - **原厂 bootloader 组合键**（NUT65 `Fn+右Shift+Esc`）用**物理修饰键影子**在吞键前判断，不受影响。
- **遗留层**：NUT65 `_FL/_MFL/_DEFA`、QK61 `_WIN_FN/_MAC_FN` 原样保留（无进入途径），不删。

## 2. 通用行为对齐（两键盘）

| 项 | 目标 |
|---|---|
| Esc | **去长按**；Insert（非宽限）=吞键进 Normal（不发 Esc）；Insert（3s 宽限内，仅由 Normal→Insert 开启）=真 Esc 留 Insert 并重置计时；Normal 空闲=真 Esc 回 Insert 并开宽限；Visual=退出选区；pending 中仅取消不发键 |
| Caps | 单击=开关 vim（开=Insert 起）；长按=临时 Normal；`Fn+Caps` 无特殊（等同裸 Caps） |
| 右 `Shift` | vim 开启时孤立不发键（避免宿主 IME 切换）；与它键同按临时补左 Shift（`右Shift+a`=`A`）；vim 关闭时正常 |
| `Shift+Esc` | **仅 Insert**：左 `Shift`=`~`、右 `Shift`=`` ` `` |
| `J` | 引擎接管 |
| `dd` | **方案 A**：取消自动双撤销；一次 `u` 只恢复一半；末行可删 |
| `x` `s` | **保留**（非新增） |
| 缩进 `>` `<` | **新增** |
| 计数 | 前缀、前后相乘（`2d3w`=`d6w`）、最多 2 位（≤99，第3位起忽略）、仅移动/缩进/行操作（含 `cc`/`S`）；`G`/`gg`/`C/D/Y/X`/`x s p P J u .`/`v V`/插入/`ZZ` 均**丢弃计数**；`S`≡`cc` 接受计数 |
| 鼠标模式 | 右 Alt **短按**（阈值 200ms，与 Caps 一致）在 Insert/Normal/Visual 均可进/出（长按=RAlt），**退出回进入前模式**；`hjkl`=指针、`Shift+J`/`Shift+K`=滚轮下/上、`Space`=左键（短/长）、`Enter`=右键、其它键退出并重新识别；删旧鼠标逻辑 |
| RGB | Insert 绿 / Normal 蓝 / pending 黄 / Visual 紫 / **鼠标模式青** / 关 红；去 replace 橙；pending 不覆盖 Visual |
| myfn | 见 §2.3 |
| 方向 | **除非键盘原生存在方向键，否则方向只用 vim Normal 的 `hjkl`** |

> **Esc 归属**：Insert/Normal 的 Esc 切换由共享层步骤 `esc_process` 负责（引擎对 Insert 一律透传）；Esc 的 pending 取消与 Visual 退出仍交给引擎。若 keymap 前置分支确需处理 Esc，须先查 `kv_pending()`/`kv_cancel()` 或直接转交 `kv_kbd(KC_ESC)`，避免 pending 未清。

### 2.1 键盘层快捷键（kept）

`BSPC→←`、`Space→→`、`-`→`Up`+`Home`、`Shift+=`→`Down`+`Home`、`Ctrl+F/B`→`PgDn/PgUp`、`/`→`Ctrl+F`。

> 这些原由 `process_normal_mode_user` 实现；删弱钩子后**定为 keymap 前置分支**：
> 在调用 `kv_kbd()` **之前**，当 `kv_get_mode()==NORMAL` **且 `!mouse_mode_active`** 时拦截这些键（自定义 Normal 处理函数），不经引擎。
> - **先清 pending**：命中时先取消引擎的半途命令（新增 `kv_cancel()`，或先喂 `Esc`），避免 `d` 后按 `BSPC`/`Space` 污染 motion。
> - **修饰键剥离**：`Ctrl+F/B`、`Shift+=` 在新引擎"不打包 / 不 `clear_mods`"下会发成 `Ctrl+PgDn`/`Shift+Home`；命中时需**临时剥离物理修饰键**再发纯键（发完恢复影子状态）。
> - **key-up**：press 被吞时其 release 也一并吞（否则宿主收到"无 press 的 release"）。
> - `Enter`/`Tab` 属"非 vim 键"，由引擎通用透传处理，**不建前置分支**（仅行为描述）。
> - 引擎侧**不新增 `normal-user` 钩子**；`vim/design.md` §4.7 仅补查询/设置接口，原三函数签名不变。

### 2.2 `process_record_user` 处理顺序

```
bootloader 组合（最高优先级；仅 NUT65）
  → 键盘专属（QK61: Fn+Esc 3s reset / Ctrl+Alt+Del；Shift+Esc 等）
  → myfn（Fn+L / Fn+右上角 / Fn+T / Fn+Space；Fn+Q/W/E/R 由厂商处理）
  → Esc 交互（Insert<->Normal 切换 + 3s 宽限）/ Caps（单击开关 vim / 长按临时 Normal）
  → 鼠标模式
  → vim 引擎（kv_kbd）
  → 透传
```

> - **QK61** 的真实结构：`qk61.c` 的 `process_record_kb` 是**外层 wrapper**，其 `default:` 才转调 keymap 的 `process_record_user`；`MD_BLE1/2/3`、`MD_24G`（Fn+Q/W/E/R）这些 case **直接 return、不经过 keymap**。
> - **`Fn+Esc` 归"键盘专属"**：QK61 为 3s 长按 EEPROM reset（需计时，不能被 myfn 提前消费）；NUT65 靠 `_FN` 的 `EE_CLR`。
> - **bootloader 组合仅 NUT65**：QK61 无 Fn 刷机组合（按住 `Esc` 插线 / PCB Reset）。
> - **QK61 实际调用顺序**：`process_record_myfn` 先于 `Ctrl+Alt+Del` / `Fn+Esc`（因无重叠键，与上示顺序等效）。

### 2.3 myfn 键负责层

- `Fn+1..0`=F1..F10、`Fn+-`/`=`=F11/F12、`Fn+[`/`]`=音量、`Fn+Space`=电量；`Caps` 单击开关 Vim（`Fn+Caps` 无特殊）。
- `Fn+Esc`=初始化（**QK61 = 长按 3s**；**NUT65 = 长按 3s `EE_CLR`**（沿用厂商语义，非短按）；见 §2.2 归键盘专属处理）。
- **`Fn+T`（切有线）分键盘**：**NUT65 = `KC_USB`**（源码中物理模式开关引脚被注释、靠键码切模式；由厂商 `nut65.c` 的 `process_record_wls` 处理）；**QK61 = 空跑**（有物理开关）。
- **`Fn+L`（休眠）/`Fn+右上角`（唤醒）**：本次迁移**有意偏离 `fn/readme` 1.1.0 引入的休眠/唤醒约定**（现文档 1.3.0）：按 `fn/readme` §1/§5「只实现自己能实现的功能」（规则 2）**不实现睡眠/唤醒功能**；为防泄漏，**拦截后吞键（空跑）**（仅删原有**手动**电源组合）。
  - NUT65：`Fn+L`/`Fn+右上角` 从未绑定；其**手动**深睡原走 `Ctrl+右Alt+Insert` 电源组合（本次移除）；**厂商自动睡眠/唤醒（`wls.c`：超时 `lpwr_set_timeout_manual`、唤醒 `LPWR_WAKEUP_*`）原样保留**，本次不触及。
  - QK61：有物理开关。
  - 实现：QK61 扩展 `process_record_myfn` 吞 `L`/右上角；NUT65 把 `_FN` 的 `L`/右上角位映射 `KC_NO`（`L` 现为 `_______`；右上角位亦然；均无 handler 依赖，安全）。
  - 右上角键：**QK61 = `KC_BSPC`（row1 col13）**；**NUT65 = `row0col14`（Win base `KC_DEL`、Mac base `KC_INS`）**——NUT65 需「删旧电源拦截 + 加新空跑」两步一起做。
  - **变更（NUT65 v2.11，2026-09）**：改为**实现** `fn/readme` 休眠约定——`Fn+L` 短按休眠（前提：无物理开关 + 非 USB 有线，否则空跑）、`Fn+右上角([0,14])` 为**唯一**唤醒组合（其它键仅瞬时唤醒后重睡）；同时**删除**原手动 `Ctrl+右Alt+Delete` 深睡组合（v2.10 的组合识别修复随之作废）。QK61 维持空跑不变。
  - 唤醒判定按物理位置 `[4,11]`(Fn)/`[0,14]`(右上角)，**任意按下顺序**均成立（v2.12 修同扫描 row0 先于 row4 的时序）。边界（已接受并见 readme §一）：①「唯一唤醒」仅约束 `Fn+L` 手动深睡，厂商 `LPWR_TIMEOUT`(5min) 自动深睡仍按任意键唤醒；②唤醒后仍按着的 `Fn` 不激活 `_FN` 层，需松开重按。
- `Fn+Q/W/E/R`（蓝牙 1/2/3、2.4G）：键码在 keymap `_FN` 层承载——
  **QK61 用 `MD_BLE1/2/3`、`MD_24G`，由 `qk61.c` 的 `process_record_kb` 处理（不经 keymap）**；
  **NUT65 用 `KC_BT1/2/3`、`KC_2G4`，由 `nut65.c` 的 `process_record_wls` 处理**。

### 3.1 底排（Space 右侧）— 按 §0.1 约定

| 物理位 | 现在 | 改为 |
|---|---|---|
| 原右 Alt 位 | `MO(4)`（Fn） | **`Alt`**：自定义键（短按=鼠标模式，长按 Win=`KC_RALT` / Mac=`KC_RCMD`） |
| 原 Menu 位 | `MT(MOD_RALT, KC_LEFT)` | **`Fn`**：`MO(4)` |
| 右 Ctrl 位 | `MT(MOD_RCTL, KC_DOWN)` | **`Menu`**：`KC_APP`（§0.1：`Menu` 在 `Ctrl` 左） |
| 原 Fn 位 | `MENU_TAP_RIGHT` | **`Ctrl`**：`KC_RCTL` |
| 右 Shift 位 | `MT(MOD_RSFT, KC_UP)` | `KC_RSFT` |

> 底排物理顺序（左→右）= `Space` `Alt` `Fn` `Menu` `Ctrl`，与 §0.1「`Alt` `Fn` `Menu` `Ctrl`」一致（右 `Shift` 在上一行 `[4,13]`，不在底排，仅作对照）。
> **Win / Mac 两套**同步：Mac 底排同理（原 `MT(MOD_RGUI,KC_LEFT)` 等按上表改；`Alt` 位长按 = `KC_RCMD`）。

- 自定义鼠标键物理在「原右 Alt 位」，功能上是"**右 Alt**"键（短按进/出鼠标模式）。

### 3.2 删除

- `MENU_TAP_RIGHT` 指针 / 长按 `KC_APP`（含 `menu_*` 状态）。
- Insert 下 `RCTL+数字` → `F1..F10`（恢复透传）。
- 旧鼠标逻辑：`spc_ms_pressed` / `ent_ms_pressed` / `ms_move_held`、`matrix_scan_user` 中 Space 拖动等。
- `Tab` 显式透传。

> ⚠️ 新 `Menu`=`KC_APP` 会被 `qk61.c` 的 `process_record_kb` **提前 `return`（不进 keymap）**，故不会走 keymap 的按键闪灯/自定义逻辑。若需要 Menu 也参与闪灯，须改用 `QK_KB` 自定义键（见 §3.5）。

### 3.3 保留（键盘专属）

`Fn+Esc` **长按 3s** = EEPROM reset（QK61 特有）；`左Ctrl+左Alt+BSPC` → `Ctrl+Alt+Del`（须左侧修饰键）；
C1 RF 状态机（`DISABLE_CUSTOM_SLEEP`）；按键短亮灯；`Key_Fn_Status`；Win 键常亮。

### 3.4 构建

- `config.h` 保留 `MYFN_LAYER`（=4）、`DYNAMIC_KEYMAP_LAYER_COUNT`（=5）。
- 编译 `make qk61:vim`。

### 3.5 QK61 特殊机制（勿动）

- **强符号 `keymap_key_to_keycode()`**：绕过 EEPROM 的 VIA 动态键位、强制走编译 `keymaps`（改底排后必须保留）。
- **VIA 同步**：`MENU_TAP_RIGHT` 本就不在任何 VIA JSON（只在 `keymap.c`）；`keyboard.json` 也**无** `customKeycodes`。
  新鼠标自定义键若要出现在 `via.json`，须用 **`QK_KB_N`**（`QK_KB_0`=0x7E00）编码，而非 `SAFE_RANGE`（=QK_USER=0x7E40，不映射到 VIA）。
  **注意**：厂商已占 `QK_KB_0..14`（`rdmctmzt_common.h`）；`via.json` 已列约 22 项（索引 `0..21`，其中 `15..21` 在固件 enum 中无对应、属厂商遗留，但**索引已被占用**）。故新鼠标键须选 **`QK_KB_22`**（首个真正空闲），并在 `via.json` 对应槽位追加同名项，保持 `via.json` 与 `CIDOO QK61 VIA.JSON` 同步（二者相同）。
- `keyboard_post_init_user()` 里 VIA 动态键位重置（`dynamic_keymap_reset()` + `QMK_BUILDDATE` 哈希）保留。

## 4. NUT65（后做，`nut65` 分支）

- 同 §1、§2 通用项。
- **底排**：含原生 `← ↓ →`（`_BL`）+ `↑`（row3 右）；**原生方向键不动**。其"非方向键"按 §0.1 归位为 **`Alt`、`Fn`**（`Alt` 在前、`Fn` 在后）。**注意**：现 vim keymap 底排为 `Space, MO(_FN), KC_RALT`（Fn 在 Alt 左），**与 §0.1 相反**，本次需**再交换**回 `Alt`、`Fn`；其 `readme.md` 声称"已对调"的描述为旧状态，需一并更正。
- **Mac base（`_MBL`）同理**：非方向键按 §0.1 归位；`Alt` 位对应 Mac 的 `KC_RCMD`（原厂 Mac base 该位即 `KC_RCMD`），鼠标键长按 Mac 版 = `KC_RCMD`。
- **删除电源组合键** `Ctrl+右Alt+Insert`：
  - 删 power-combo 组：`pr_power_ins`、`pr_power_mods`、`pw_off`、`pw_ctrl`、`pw_ralt`、`pw_ins`、
    `pw_combo`、`pw_combo_latch`、`pw_combo_timer`、`pw_enter_sleep`、`pw_boot_wireless`、Insert 位（row0col14）拦截。
  - **保留自动切换组**（勿删）：`pw_last_wls`、`pw_frozen_wls`、`pw_frozen_valid`、`pw_last_valid`、
    `pw_wired_prev`、`pw_cable_timer`、`pw_recover_armed`、`pw_no_cable()`、`wireless_devs_change_user`
    （服务于 USB/无线自动切换与拔线回退）。
  - `KC_RALT`/`KC_LCTL`/`KC_RCTL`：移除电源组合后不再有 `pw_off` 吞修饰键分支。
  - **去门控改造**：自动切换块原被 `if (!pw_off) { ... }` 包裹，且 `housekeeping` 另有 `if (pw_off && …)` 的"插 USB/回有线恢复"分支（约 L761）；删 `pw_off` 后这两处都需去掉/迁移。
- **保留 `pr_boot_combo`（`Fn`+右`Shift`+`Esc` → bootloader）**：`fn/readme.md` §2 最高优先级保命键；**须把原 `get_mods()` 判定改为物理修饰键影子**（吞掉 RShift 后 `get_mods()` 不再含 RShift，组合会失效）；其 `wait_ms(50)` 属保命键特例，不受"引擎禁用 `wait_ms`"约束。
- **手动深睡/唤醒取消**：不新增 `Fn+L`/`Fn+右上角` 绑定（见 §2.3）；**厂商自动睡眠/唤醒（`wls.c`）保留**。
- **删除 `alt_tab_held`** 与旧鼠标逻辑（方向键 / Space / End）。
- 右 Alt 位 = **自定义键**（短按=鼠标模式，长按=`KC_RALT`）。
- 保留：原生 `← ↓ → ↑`、USB/无线自动切换、拔线回退、`mouse_link_ok` 门控、电量条、rgbrec。
- **刷后刷新**：NUT65 无 QK61 那样的强符号 `keymap_key_to_keycode`；改 `_BL`/`_FN` 键位后需
  **`EE_CLR` / VIA 重置**刷新 EEPROM 动态键位，否则被旧键位遮蔽。验证时执行一次。
- 编译 `make leku/nut65:vim ALLOW_WARNINGS=yes`。
